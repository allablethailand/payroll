# ประวัติต่อบรรทัด: จาก dropdown + modal → ตารางใต้บรรทัด (H-ui, 2026-09-19)

**เดิม** มี 2 พื้นผิวสำหรับรายการเดียวกัน (dropdown ~5 แถวหลัง badge + modal timeline ซ้อนบนสลิป) และทั้งคู่
โชว์ได้เฉพาะ `source_type='override'` ทั้งที่ H-backend (d70c1ef5) บันทึก manual line กับคำตอบ tri-state
tax/SSO ไว้ในตารางเดียวกันแล้ว · **ตอนนี้** badge เป็นปุ่ม disclosure กางตารางใต้บรรทัดนั้นเอง — กฎเต็มอยู่ใน
`docs/design/rules.md` §5

## ทำไม
- 2 พื้นผิว = รายการเดียวกัน 2 ที่ ผู้ใช้ต้องจำว่าอันไหนโชว์ครบ · modal ซ้อน modal สำหรับข้อมูลของแถวเดียว
  คือการพาออกจากที่ที่กำลังอ่านอยู่
- restore เคยมี 3 ทาง (หัว dropdown / ปุ่มใน modal / `#btnLineFormUseComputed`) ทำเรื่องเดียวกัน — และรอบ R1
  เคยทำให้หัว dropdown กดไม่ได้จนไม่เหลือ producer ของ `lo-history-computed` เลยโดยไม่มีใครเห็น

## สิ่งที่ต้องตัดสินและไม่ชัดในตัวเอง
- badge นับจาก `line-history` (3 source) ส่วน `line-override-history` + `edit_count` ของรายงาน Audit
  **ไม่ถูกแตะเลย** → นิยาม "จำนวนการแก้" ระดับรอบกับระดับบรรทัดต่างกันโดยตั้งใจ (BACKLOG ฉ)
- แถว "ค่าระบบ" มีได้ 0–2 แถว: จำนวนเงิน (เฉพาะบรรทัดที่มีประวัติจำนวนเงินจริง) และ/หรือ คำตอบ (TH_PIT/TH_SSO)
  — manual line ไม่มีเลย · "ใช้ค่านี้" ยิง 4 ปลายทางตัดสินจาก **ชนิดของ entry** ไม่ใช่จากที่กด
- **แถวเก่าที่ค่าซ้ำค่าปัจจุบัน = ปุ่ม disabled** (เจอจริง EM009/LOAN_REPAY 18:08 กับ 12:06 "→ 4,000.00"
  กดได้ทั้งคู่ ทั้งที่ backend รับแล้วไม่บันทึกอะไร) — เทียบค่าดิบ + tolerance ไม่ใช่สตริงที่ format แล้ว
- แผง: `sticky left:0` + กว้าง `clientWidth` ที่วัดจริง + `overflow-x:hidden` (บั๊กเดียวกับที่ทำให้ยอดรวม
  3 แถวต้องย้ายออกนอก scroller) + สูงสุด หัว + 6 แถว วัดจากแถวจริง + หัวคอลัมน์ sticky + ปุ่ม "ปิด" ในหัว
