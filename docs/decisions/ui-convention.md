## UI Convention
- Design: glassmorphism, สีหลัก orange `#FF9900` + gold accent, รองรับ 2 ภาษา TH/EN แบบ dynamic (เปลี่ยนได้โดยไม่ reload หน้า ผ่าน language switcher มุมขวาบน)
- Alert/Confirm ทั้งหมดใช้ **SweetAlert2** เท่านั้น (`showSuccess`/`showWarning`/`showError`/`showConfirm` ใน `public/js/alert.js`) ห้ามใช้ Bootstrap modal หรือ native `alert()`/`confirm()` สำหรับแจ้งเตือน
- ปุ่มหลัก (Add/Save) ต้องเป็นสี brand orange `#FF9900` ไม่ใช่สี Bootstrap default

### Dropdown / Select
- ทุก dropdown ในระบบต้องใช้ **Select2** ห้ามใช้ `<select>` เปล่าไม่ init — ปล่อยเป็น plain select ครั้งเดียวก็แปลภาษาไม่ได้ (option โชว์เป็น i18n key ดิบๆ ทันทีที่ key ไม่ตรง เจอเคสจริงมาแล้วในหน้า Payroll Cycle)
- Initialize ผ่านฟังก์ชันกลาง `initSelect2(selector, options)` ใน `public/js/input.js` รองรับ 3 โหมด อย่าเขียน select2 init ซ้ำใหม่ในแต่ละหน้า:
  - `{ mode: 'ajax' }` (หรือใช้ alias `initSelect2Remote(selector)`) — โหลดจาก DB ผ่าน endpoint ที่คืนค่า `{status, data: {items:[{id, text_th, text_en}], total_count}}`
  - `{ mode: 'static' }` — ตัวเลือก hardcode ไม่ผ่าน AJAX อ่านจาก `data-option-keys="key1,key2,..."` บน `<select>` แล้ว map แต่ละ key ผ่าน `getLangValue(key)`; **ต้องเช็คว่าทุก key ที่ใส่มีอยู่จริงใน `public/lang/en.json`/`th.json` ทั้งคู่ก่อนใช้งาน** ไม่งั้น fallback เป็นการโชว์ key ดิบแทนข้อความแปล
    - **ค่าที่ submit ไปหลังบ้านคือ key ตรงๆ ไม่ใช่แค่ตัวช่วยหา text** — ถ้า backend ต้องการ enum ที่ไม่ตรงกับ i18n key ที่ใช้แสดงผล (เช่น key `calc_fixed_amount` ไว้กันชนกับ key อื่น แต่ backend ต้องการแค่ `fixed_amount`) **ต้องใส่ `data-option-values="value1,value2,..."` เรียงตำแหน่งให้ตรงกับ `data-option-keys` เสมอ** ไม่งั้น select2 จะ submit ค่า key ดิบไปแทน validation หลังบ้านจะ reject ทันที (เจอบั๊กจริงมาแล้ว — บันทึกไม่ลงทั้งหน้า Payroll Configuration เพราะพลาดจุดนี้)
  - `{ mode: 'native' }` — คง native look ไม่มี dropdown UI ของ Select2 แต่ยัง init ผ่านฟังก์ชันนี้เพื่อให้ผ่านกฎ "ห้ามปล่อย select ไม่ init"
- เปลี่ยนภาษาแบบ dynamic: option label ต้องเปลี่ยนตาม language switcher ทันทีโดยไม่ reload หน้า — `applyLanguage()` ใน `public/js/app.js` จัดการ re-init ให้อัตโนมัติทั้ง `.select2-remote.select2-hidden-accessible` และ `.select2-static.select2-hidden-accessible` อยู่แล้ว ไม่ต้องเขียนเพิ่มเอง แค่ใส่ class ให้ถูก
- Placeholder, "no results found", "searching..." ต้อง localize ผ่าน `langData` เสมอ (key: `select_option`, `no_results`, `searching`, `input_too_short`) ห้าม hardcode ข้อความอังกฤษ
- ต้องรองรับ dropdown ที่อยู่ใน Bootstrap modal และ nested tab — ตั้ง `dropdownParent` ให้ชี้ modal ที่ครอบอยู่เสมอ (`initSelect2` เช็ค `$this.closest('.modal')` ให้อัตโนมัติแล้ว) ป้องกันปัญหา z-index/scroll ที่ Select2 เจอบ่อยเวลาอยู่ใน modal
- ตัวอย่างการใช้งานจริงในโปรเจกต์: dropdown ประเทศใน Company Profile/Payroll Configuration (`ajax`), dropdown ธนาคารใน Bank Accounts (`data-api="/api/bank.get" data-type="bank"`, `ajax`), dropdown Calculation Method/Tax Treatment ใน Payroll Configuration (`static`)

### Date Picker (`.datepicker`, `initDatepicker()` ใน `public/js/input.js`, ใช้ bootstrap-datepicker)
- **2026-08-26, real bug found and fixed (explicit bug report: "คลิกที่ช่องวันที่ แต่ยังไม่ได้เลือกอะไร แล้วกดข้างนอกวันที่หาย ต้องไม่หาย")** — ทุกครั้งที่โค้ดตั้งค่าฟิลด์ `.datepicker` ด้วย jQuery `.val(...)` ตรงๆ (ไม่ผ่าน widget ของ bootstrap-datepicker เอง) ต้องเรียก `.datepicker('update')` ตามหลังทันที ไม่งั้นจะเจอบั๊กนี้: widget เก็บ state ภายในของตัวเอง (`this.dates`) แยกจากค่าที่ browser แสดงในกล่อง input — `initDatepicker()` มักถูกเรียกตอนหน้าโหลดครั้งแรกตอนฟิลด์ยังว่างเปล่า (ก่อนข้อมูลจริงจะมาจาก AJAX) ทำให้ `this.dates` เป็น `[]` ค้างไว้ แม้ภายหลังจะเซ็ตค่าจริงผ่าน `.val()` ก็ตาม (ฟิลด์แสดงวันที่ถูกต้องบนหน้าจอ แต่ widget ไม่รู้) — พอ user คลิกเข้าไปในฟิลด์นั้น (เปิด picker) แล้วคลิกออกไปโดยไม่เลือกอะไรใหม่ bootstrap-datepicker's `hide()` จะเช็ค `forceParse` (default `true`) แล้วเรียก `setValue()` ซึ่งเขียนทับ input ด้วยค่าที่ format จาก `this.dates` (ที่ยังว่างอยู่) — ฟิลด์เลยว่างเปล่าไปทันทีทั้งที่ user ไม่ได้แตะอะไรเลย ยืนยัน root cause ตรงจาก source ที่ bundle มาจริง (`node_modules/bootstrap-datepicker/js/bootstrap-datepicker.js`'s `hide()`/`setValue()`/`getFormattedDate()`) ไม่ใช่การเดา
- **แก้แล้วที่ 2 จุดใน `public/js/employee/detail.js`**: `populateEmployeeForm()` (โหลดข้อมูลพนักงานเข้าฟอร์มหลักทุกแท็บ) และ `populateEedForm()` (`#eed_effective_date` ตอนเปิดแก้ไข Earning/Deduction) — ทั้งคู่เพิ่ม `.datepicker('update')` ต่อจาก `.val(...)` **ถ้าเจอบั๊กแบบเดียวกันนี้ในหน้าอื่นที่ set ค่า `.datepicker` แบบ programmatic (ไม่ใช่ user พิมพ์เอง) ให้เช็คจุดนี้ก่อนเป็นอันดับแรก** — ปลอดภัยที่จะเรียก `.datepicker('update')` ซ้ำแม้ field จะยังไม่เคย init ก็ตาม (แต่ในเคสจริงของโปรเจกต์นี้ `initDatepicker()` มักรันตอน document ready ไปแล้วก่อนหน้าฟังก์ชัน populate ใดๆ จะถูกเรียก)

### Date Display Format (`formatDisplayDate()`/`formatDisplayDateTime()` ใน `public/js/app.js`)
- **2026-08-26, explicit request: "Format วันที่การแสดงผลทั้งหมดของระบบให้เป็น dd/mm/yyyy"** — ตรวจสอบทั้งโปรเจกต์แล้วพบว่าหลายหน้ามี local helper ของตัวเองอยู่แล้วที่ทำแบบนี้ถูกต้อง (`employee/detail.js`'s `toDisplayDate()`, `payroll/approval.js`'s `toDisplayDateAp()`, `payroll/index.js`'s `toDisplayDatePr()`, `payroll/detail.js`'s `toDisplayDateRd()`) — **ของเดิมเหล่านี้ไม่แตะ** เพราะทำงานถูกต้องอยู่แล้ว แก้โค้ดที่ทำงานถูกอยู่แล้วโดยไม่ได้อะไรเพิ่มมีแต่ความเสี่ยง จุดที่แก้จริงคือช่องที่ยัง render วันที่แบบ raw ISO (`YYYY-MM-DD`) ตรงๆ ไม่ผ่าน formatter ใดๆ เลย: `reports/index.js`'s `generated_at`, `setup/payslip-delivery-log.js`'s `sent_at`+pay-period display, `setup/payslip-request.js`'s `created_at`+pay-period display, `setup/employment-certificate-request.js`'s `created_at`, `payroll/detail.js`'s audit-log `performed_at`, `setup/tax-statutory.js`'s rate-history `effective_date`/`end_date`, `employee/list.js`'s `start_work_date`, และ `setup/approval-request-detail.js`'s `requested_at`/`acted_at` (ไฟล์ที่เพิ่งสร้างในเซสชันเดียวกันนี้เอง)
- **เพิ่ม `formatDisplayDate(value)`/`formatDisplayDateTime(value)` ใน `public/js/app.js`** (โหลดทุกหน้าอยู่แล้ว, ก่อน `input.js`) สำหรับช่องที่ยังไม่มี local helper ของตัวเอง — **ตั้งชื่อไม่ซ้ำกับ `toDisplayDate*()` เดิมโดยตั้งใจ** เพราะการประกาศ `function` ชื่อเดียวกันซ้ำที่ global scope ใน non-module script ไม่ error แต่ผลลัพธ์ขึ้นกับลำดับโหลดไฟล์ (fragile) — บั๊ก category เดียวกับที่เคยเจอจริงมาแล้วใน `payslip-template.js`/`employment-certificate-template.js` (ดู Payslip Format section)
- **DataTables ที่เป็น client-side (ไม่มี `serverSide:true`) ต้องใช้ object-form `render: { display: fn, sort: rawFn, filter: rawFn }` ไม่ใช่ plain `render: fn`** เมื่อ column นั้นอาจถูกใช้ sort — เพราะ DataTables client-side sort/filter จะใช้ค่าที่ผ่าน `render()` แล้ว (ค่าเดียวกับที่ใช้ display) ถ้าไม่แยก type ไว้ การ format เป็น `dd/mm/yyyy` string จะทำให้ sort กลายเป็น lexicographic string sort ("05/09" มาก่อน "26/08") แทนที่จะเป็น chronological order จริง — DataTables ที่เป็น `serverSide:true` (เช่น `employee/list.js`) ไม่มีปัญหานี้เพราะ sort ทำที่ SQL ORDER BY บน raw column โดยตรง ไม่เกี่ยวกับ client render เลย
- **ฝั่ง PDF ก็เจอจุดเดียวกัน**: `PayslipTemplateRenderer::buildTokens()`'s `pay_period`/`payment_date` tokens และ `PaySlipReport::buildHtml()` (fallback layout ตอนบริษัทยังไม่ได้ตั้งค่า canvas template — เคสที่พบบ่อยกว่า) กับ `PaymentVoucherReport` ล้วน embed ISO date ดิบเข้า PDF ตรงๆ — เพิ่ม private `formatDate()` (เหมือนกับที่ `EmploymentCertificateRenderer::formatDate()` มีอยู่แล้ว, 3 บรรทัด ไม่คุ้มที่จะดึงออกเป็น shared trait) ที่ทั้ง 3 ไฟล์ **statutory export (ภ.ง.ด., สปส. ฯลฯ) ไม่แตะ** เพราะต้องตามฟอร์แมตราชการที่กำหนดไว้ตายตัว ไม่ใช่ขอบเขตของ request นี้

### Table / รายการข้อมูล
- ทุกตารางที่แสดงรายการข้อมูล (list) ต้องใช้ **DataTables** ห้ามปล่อยเป็น `<table>` เปล่าไม่ init หรือ render แถวเองแบบ manual แล้วจบ (ย้อนกลับไปเป็นแบบนั้นเคยเกิดขึ้นจริงตอนสร้างหน้า Payroll Cycle จาก mockup เดิม)
- เลือกโหมดตามขนาดข้อมูลที่คาดว่าจะมี:
  - **Server-side** (`serverSide: true`) สำหรับรายการที่อาจมีจำนวนมากไม่จำกัด (พนักงาน, master catalog ต่อบริษัท) — endpoint ฝั่ง PHP ต้องคืนค่าตรงตาม DataTables spec: `{draw, recordsTotal, recordsFiltered, data}` (ดูตัวอย่าง `EmployeeController::list()`, `PayrollConfigurationController::pedTypeList()`)
  - **Client-side** (`ajax` + `dataSrc`) สำหรับรายการที่รู้แน่ชัดว่าน้อยต่อบริษัท (เช่น payroll cycle) — endpoint คืนค่า `{status, data:[...]}` ธรรมดาแล้วตั้ง `dataSrc: 'data'` ดึงออกมาพอ ไม่ต้องทำ server-side pagination
- ปุ่ม "Add" ต้อง inject เข้าไปในแถบค้นหาของ DataTable เองผ่าน `initComplete` (หา container แล้ว append ปุ่มสีส้มเข้าไปใน `.dt-search`) ห้ามวางปุ่มลอยแยกเหนือ/ข้างตาราง
- ปุ่ม Edit ต้องดึงข้อมูลสดจาก API เสมอ (`GET .../xxx.get?id=`) ห้ามอ่านจากข้อมูลที่ cache ไว้บน DOM ของแถว เพราะ DataTables อาจ re-render แถวเมื่อเปลี่ยนหน้า/sort/ค้นหา ทำให้ cache หลุด
- Save/Delete สำเร็จให้ reload ด้วย `table.ajax.reload(null, false)` (พารามิเตอร์ตัวที่สอง `false` = ไม่รีเซ็ต pagination ที่ผู้ใช้อยู่) ห้าม reload ทั้งหน้า
- ตัวอย่างการใช้งานจริงในโปรเจกต์: ตารางพนักงาน/Earning-Deduction Types (server-side), ตาราง Payroll Cycle (client-side)
- **ทุก `<th>` ที่มีข้อมูลจริง (ไม่ใช่คอลัมน์ปุ่มดำเนินการ/ไอคอนล้วนๆ/widget ภาพ เช่น mini-timeline) ต้องมีทั้ง sort และ filter** — ตาราง**ใหม่**ทุกตารางต้องเรียก `initExcelColumnFilters(dt, options)` (`public/js/table-column-filter.js`, โหลดทุกหน้าอยู่แล้วผ่าน `header.php` แต่ต้องเรียกเองต่อตาราง ไม่ใช่ auto-wire) ใน `initComplete` เสมอ ไม่ใช่ทำ filter เองแบบ ad-hoc — 2 โหมด: `mode:'client'` (ตาราง `ajax`+`dataSrc`/`data:` array ธรรมดา ไม่ใช่ `serverSide:true` — ค่า unique ดึงจาก rendered cell text ของทั้ง dataset ที่โหลดมาแล้ว) หรือ `mode:'server'` (`serverSide:true` ต้องมี backend distinct-values endpoint จริงต่อคอลัมน์ ผ่าน `fetchValues(key, done)` + `onApply()` reload) ดู docblock เต็มในไฟล์นั้นเอง — ฟังก์ชันนี้สร้าง sort-arrow ให้เองอัตโนมัติถ้าคอลัมน์นั้น sortable อยู่แล้ว (เช็คจาก DataTables' เอง `bSortable`/`oFeatures.bSort`) ไม่ต้องทำ sort UI แยกเอง
  - **คอลัมน์ที่แสดงผลเป็น formatted/HTML string ต่างจากค่าที่ใช้ sort/filter จริง (วันที่ dd/mm/yyyy, ตัวเลขมี comma, badge) ต้องใช้ object-form `render: {display, sort, filter}` เสมอ ไม่ใช่ `render: fn` เดี่ยวๆ** ไม่งั้น DataTables client-side sort/filter จะทำงานผิดบนค่าที่ format แล้ว (string sort ของ "05/09" มาก่อน "26/08", หรือ "1,234.56" มาก่อน "999.00") — `sort`/`filter` ให้คืนค่าดิบ (ISO date string หรือ raw number) เสมอ — เจอบั๊กนี้จริงมาแล้วหลายรอบ (Process List/Approval List/Employee Detail's Earning-Deduction+Recurring Earning tables ฯลฯ แก้ไปแล้วทั้งหมดในรอบ 2026-08-29 ที่เจอผ่านการ audit ทั้งระบบ)
  - **exempt ได้เฉพาะ**: คอลัมน์ปุ่มดำเนินการล้วนๆ (Edit/Delete/ไอคอน), widget ภาพที่ไม่มีค่าเดี่ยวให้ filter (mini-timeline, progress bar, avatar), หรือตารางที่ตั้งใจปิด `ordering:false` ทั้งตารางแล้วมี filter หลักระดับบนอยู่แล้ว (เช่น Login History ที่เป็น `serverSide:true` พร้อม top-level filter บริบทเฉพาะ — ดู `employee/detail.js`'s `#tableLoginHistory`/`employee/list.js`'s `#tb_login_history_overview` เป็นตัวอย่าง "จงใจไม่ใส่" ที่มี comment อธิบายเหตุผลไว้)
  - **Filter รูปแบบอื่นที่ไม่ใช่ per-column** (เช่น ช่วงวันที่ ที่ Excel-column-filter แบบ discrete-value ทำไม่ได้) ให้ใช้ component `.station-filter` (label + chevron-toggle ปุ่ม + `.station-filter-body` เป็น `row g-2` ของ field, ปุ่ม "Clear Filter" แยกไว้ข้างล่างโชว์เฉพาะตอนมี filter active) แบบเดียวกับ Employee List/Process List/Notifications — ห้ามสร้าง filter row แบบ `d-flex gap-2` เอง
