# slip2-b — สลิปเป็น modal-xl, แผงข้อมูลดิบเป็นการ์ดต่อหัวข้อที่คุมความสูงตัวเอง (2026-09-22)
rules.md §5/§9 · ต่อจาก [slip2-a](2026-09-22-slip2a-line-table.md) และ [3e-2b](2026-09-21-3e2b-slip-sync-panel.md)

**หน้าต่างลูกที่กว้างเท่าแม่ ไม่ใช่หน้าต่างลูก** — วัดก่อนแก้: `.modal-content` ของสลิปกับของฟอร์มบรรทัด = **800 เท่ากันเป๊ะ** (ทั้งคู่ `modal-lg`) เปิดฟอร์มจึงอ่านเป็น "เปลี่ยนเนื้อในกล่องเดิม" · สลิปมีตารางอยู่ในตัว ซึ่ง §9 สงวน `modal-xl` ไว้ให้อยู่แล้ว → สลิป 1140 / ฟอร์มคง 800 = **ห่าง 340** · ที่ < `lg` ทั้งคู่เต็มจอเท่ากัน ไม่มีอะไรเปลี่ยนที่ 430

**ห้ามแก้ด้วยการย่อฟอร์ม** — `.segmented`'s ป้ายสั้นสลับที่ `max-width: 575.98px` ซึ่งเป็น **viewport** ไม่ใช่ความกว้างกล่อง ฟอร์มที่ถูกบีบให้แคบที่ viewport 1400 จะได้ป้ายเต็ม ("โอนให้บุคคล/องค์กรภายนอก") ในกล่องที่ไม่พอ — คลาสเดียวกับบั๊ก `col-md-6` ที่ 3e-2b เจอ · s10 วัด `scrollWidth ≤ clientWidth` ของทุกป้ายไว้กันพลาดซ้ำ

**3 กรอบซ้อน ให้ตัดชั้นนอก ไม่ใช่ชั้นใน** — 3e-2b ถอดขอบของ section ออกด้วยเหตุผล "กล่องในกล่องไม่ได้บอกอะไร" ซึ่งถูก แต่ชั้นที่บอกน้อยที่สุดคือ **ชั้นนอก** (มันจัดกลุ่มสิ่งที่หัวข้อจัดให้แล้ว) · slip2-b จึงคืน panel rule §5 (`--c-bg` + `1px --c-border` + `--radius` + padding) ให้ `.rd-sync-section` แล้วถอด border/padding ของ `.rd-sync-panel` ทิ้ง — วัดหลังแก้: section border 1px / panel border 0px

**"รายการเพิ่มเติม" เป็นการ์ด แต่อยู่นอกกริด** — เดิมเป็นหัวข้อลอยใต้กริด ทั้งที่เป็นของที่ Origami ส่งมาเหมือนกัน · รอบแรกใส่เข้ากริดด้วย `grid-column: 1 / -1` แล้ว**พังทันที**: ผู้ใช้ส่งภาพสลิปที่ซ่อน section การเข้างาน ได้การ์ด 2 ใบแคบ ๆ ครึ่งขวาของแผงว่าง · เหตุ — **`auto-fit` ยุบได้เฉพาะ track ที่ว่าง** และ item ที่ span `1 / -1` กินทุก track จึงไม่มีอะไรว่างให้ยุบ (วัด: `grid-template-columns` = `270px 270px 270px 270px` ไม่ว่าจะมีการ์ด 3 หรือ 2 ใบ) · แก้เป็น **sibling ของกริด** — ยังเต็มความกว้างเพราะเป็น block ระยะใช้ `margin-top: --sp-3` เท่ากับ gap ของกริด
**วัดหลังแก้ที่แผง 1116px**: 3 ใบ → 364/ใบ (field cols 3) · 2 ใบ → 552/ใบ (4) · 1 ใบ → 1116 (10) · ผลรวม + gap = ความกว้างแผงพอดีทุกกรณี · เพดาน scroll box ยังตามความสูงแถวแรกจริง (130 ที่ 2 ใบ, 86 ที่ 1 ใบ)

**เพดานความสูง = 1 แถวของการ์ดที่ render จริง** — วัดจาก DOM แบบเดียวกับ `lineOverridePublishHistoryHeightRd()` ไม่ประกาศเลข เพราะการ์ดที่มี callout สูงไม่เท่าการ์ดเปล่า · `min(..., 45vh)` กันเคสการ์ดเดียวสูงมาก (ที่ 430 หนึ่งแถว = หนึ่งการ์ด) · re-publish ด้วย ResizeObserver เพราะ "ใครอยู่แถวแรก" ตัดสินจากความกว้างของแผง
**ผลที่ต้องการ วัดได้จริง**: ก่อนแก้ แถวแรกของตารางจบที่ y 853.7 ขณะที่ modal-body จบที่ 796 (**ต่ำกว่าขอบจอ 57.7px** — เปิดแผงมาเทียบตัวเลขแล้วเห็นได้ทีละอย่าง) · หลังแก้ 609.5 ≤ 796 และ `scrollTop = 0`

**scroll box ต้องโฟกัสได้** — `tabindex="0" role="group" aria-label` ทั้งแผงข้อมูลดิบและ `.lo-history-scroll` · แถวในกล่องแท็บถึงอยู่แล้ว แต่ **การเลื่อน** ไม่ถึง คนที่ใช้คีย์บอร์ดจึงอ่านประวัติเกินแถวที่ 5 ไม่ได้ (แผงประวัติ cap ที่ 5 แถวตั้งแต่ H-ui)
