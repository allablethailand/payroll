# สลิปที่แก้ได้ — D2: block "รายการที่เพิ่มเอง" ใช้งานได้จริง (2026-09-17)

ต่อจาก `2026-09-16-breakdown-editable-slip.md` (D1) ที่วาง block นี้ไว้พร้อมปุ่ม `+` ที่ **disabled**
พร้อม tooltip "ยังใช้ไม่ได้" — รอบนี้คือทำให้ใช้ได้จริง: เพิ่ม / แก้ / ลบ รายการที่คนเพิ่มเอง จากที่เดียวกับ
ที่กำลังอ่านตัวเลขอยู่

## ฟอร์มมีชุดเดียวในแอป ไม่ใช่ของ tab แล้วก๊อปไปที่สลิป

คำสั่งของรอบนี้ระบุว่า "ย้ายเป็น shared ตัวเดียว ห้ามก๊อป" และ "ฟอร์มใน tab 1 ต้องเรียก shared ตัวเดียวกัน"
ซึ่งมี 3 ทางที่เป็นไปได้ — **ถามก่อนเขียน** (ไม่เดา, §0.6) แล้วผู้ใช้เลือกทางแรก:

| ทาง | ผล |
|---|---|
| **ย้ายฟอร์มเข้า modal ซ้อนที่เดียว** (เลือก) | markup ชุดเดียวอยู่ใน `#manualLineFormModal`; tab "รายการจ่าย" ตัดฟอร์ม inline ทิ้งแล้วเปิด modal เดียวกันผ่านปุ่ม `+` บนหัวคอลัมน์ เหมือน block ใน Breakdown เป๊ะ |
| ย้าย DOM node เข้า-ออกตอนเปิด/ปิด | ไม่มีสำเนาเหมือนกัน แต่เพิ่ม DOM reparenting ซึ่ง `rules.md` §6 (filter-bar) เตือนไว้แล้วว่าเป็นบ่อเกิดบั๊ก handler หลุด |
| partial รับ `prefix` include 2 ที่ | ได้ 2 instance จริง ต้องรื้อ handler ทุกตัวใน `payroll/detail.js` ให้เป็น prefix-generic ทั้งชุด |

ทุก field ใน modal **ใช้ id เดิมทั้งหมด** — handler เดิมของ payee picker / mode toggle / money input
จึงทำงานต่อได้โดยไม่ต้องแก้ ย้ายแค่ที่อยู่ของ markup

`#btnAddManualLine` (ปุ่มในฟอร์ม) กลายเป็นปุ่มใน footer ของ modal สร้างด้วย `modalFooterButtonsHtml()`
**ต่อการเปิด 1 ครั้ง** (ไม่ใช่สร้างครั้งเดียวแล้ว toggle) เพราะสิ่งที่ต่างกันระหว่าง "เพิ่ม" กับ "แก้" คือ
**ป้ายของปุ่มหลัก** ซึ่งเป็นเรื่องตอน build ไม่ใช่ `disabled`/`d-none` — id ใหม่คือ `#btnSaveManualLine`
(ปุ่มเดียวทำทั้ง 2 อย่าง)

## แก้ backend 1 บรรทัด — ถามก่อนตามกฎ

`manualLinesForEmployee()` ไม่เคยคืน `ped_type_id` ออกมา (SQL ดึงมาแล้ว แต่ไม่ได้ใส่ใน array) ทำให้
prefill โหมด catalog เป็นไปไม่ได้เลย เพราะ select2-remote ไม่มี option ในมาร์กอัปให้ match — คำสั่งรอบนี้
บอกว่า "ถ้าพบว่าต้องแก้ backend หยุดถามก่อน" จึงหยุดถาม ผู้ใช้อนุมัติให้เพิ่ม field นี้ใน read payload
(read-only, ไม่แตะ write path/การคำนวณ) · ที่เหลือที่ prefill ต้องใช้มีครบอยู่แล้ว
(`item_name_th/en`, `destination_id` + `destination_account_name`, `bank_account_id` +
`bank_account_name`, `payee_employee_no`)

## host 2 ตัว ตัดสินจาก mount ที่ถูกกด ไม่ใช่ตัวแปร "host ปัจจุบัน"

ต่างจาก `lineOverrideHostRd` (D1) ตรงที่ block นี้ **อยู่พร้อมกันได้ 2 ที่จริงๆ** — Adjustments modal ยัง
render ค้างอยู่ใต้ Breakdown modal ได้ตลอด — ตัวแปร "host ปัจจุบัน" ตัวเดียวจึงถูกเขียนทับกันเองได้
`manualLineHostForMountRd($mount)` เลยตอบจาก `.ml-mount` ที่คลิกเกิดขึ้นข้างในแทน คืน 3 อย่าง: พนักงานคนไหน,
แก้ได้ไหม, และหลังบันทึกต้องรีเฟรชอะไร (Breakdown: block + ยอดสุทธิจาก server + ตาราง run / tab 1: block +
ตาราง run)

## gate เดียวกับ server ทั้ง 2 host

`breakdownCanEditRd()` เปลี่ยนชื่อเป็น `employeeRowEditableRd()` เพราะไม่ใช่คำถามของ Breakdown modal
อย่างเดียวอีกต่อไป — `assertManualLinesEditable()` (PayrollRunModel) ปฏิเสธ **รอบที่ไม่ใช่ draft** และ
**พนักงานที่ถูกยืนยันแล้ว** สำหรับ add/update/remove ทุกตัว ดังนั้น tab "รายการจ่าย" ที่เมื่อก่อนโชว์ฟอร์มให้
เสมอ (แล้วไปโดน error ตอนกดบันทึก) ตอนนี้ปุ่ม `+` จะ disabled พร้อมเหตุผลใน tooltip แทน

ผลข้างเคียงที่ตั้งใจ: tab "รายการจ่าย" ไม่มีฟอร์มเหลือแล้ว → ตั้ง `immediate: true` ใน
`ADJUSTMENT_TAB_CONFIG_RD` (ซ่อนปุ่มบันทึกของ footer + ปิด dirty guard ของ tab นั้น ตาม §9)

## error จาก server อยู่ในฟอร์ม ไม่ใช่ dialog ทับฟอร์ม

`showError`/`showWarning` เป็น dialog กลางจอ ซึ่งจะ**บังค่าที่เพิ่งถูกปฏิเสธ** — modal นี้จึงมี slot
(`#manualLineFormError`) ที่ render `calloutHtml(msg, 'danger')` (§15) ไว้บนสุดของ body และ **ไม่ปิด modal**
`manualLineFormPayloadRd()` จึง **คืน** ข้อความปฏิเสธออกมา แทนที่จะแสดงเอง (validation ฝั่ง client 3 จุดเดิม
เปลี่ยนจาก `showWarning(...); return;` เป็น `return { ok: false, message }`)

ทดสอบด้วยการปฏิเสธจริงจาก server ไม่ใช่การจำลอง: เปิดฟอร์มค้างไว้ → ยิง `employee-verify.save` ให้พนักงาน
คนนั้นถูกยืนยัน (แช่แข็งตัวเลข) → กดบันทึก → ได้ข้อความจริงจาก `assertManualLinesEditable()` ในฟอร์ม
modal ยังเปิดอยู่ ค่าที่พิมพ์ยังอยู่ครบ block ไม่เปลี่ยน

**ข้อจำกัดที่ flag ไว้ (ไม่ใช่ของใหม่จากรอบนี้)**: ข้อความปฏิเสธจาก model เป็นภาษาอังกฤษล้วนทั้งแอป
(`'This employee is verified for this run...'`) — ข้อความที่ UI เขียนเองผ่าน lang th/en ครบ แต่ของที่ server
ส่งมาไม่ได้ผ่าน i18n มาตั้งแต่ต้น ถ้าจะแก้ต้องทำเป็นงานแยกทั้งชั้น model

## แถว: ปุ่มกลม 32px ท้ายแถว แสดงตลอด + ทั้งแถวกดได้

ของเดิมเป็นปุ่มลบ ghost 20px ที่โผล่ตอน hover และถูกวาง `position: absolute` ไว้ขอบซ้ายของเซลล์จำนวนเงิน
(เพื่อไม่ให้ตัวเลขขยับ) — รอบนี้เปลี่ยนเป็น `.btn-icon` 32px (§7) 2 ปุ่ม (ดินสอ/ถังขยะ) **ท้ายแถว แสดงตลอด**
เหตุผลเดียวกับที่ §6 สรุปไว้แล้วกับ comment list: affordance ที่ต้อง hover ก่อนถึงจะรู้ว่ามี ไม่นับเป็น
affordance — และตอนนี้แถวมี 2 action ไม่ใช่ 1

เซลล์จำนวนเงินกลายเป็น flex row ผ่าน `<div>` ข้างใน **ไม่ใช่ที่ `<td>`** (§7: `display:flex` บนเซลล์ฆ่า
table-cell + colspan ของมัน — บั๊กจริงจาก D1) ตัวเลขได้ `min-width: 0` + ellipsis เพราะตารางสลิปเป็น
`table-layout: fixed` ความกว้างเซลล์มาจากตาราง ไม่ใช่เนื้อหา

แถวที่ **ไม่มี `id`** (บรรทัดเก่าที่บันทึกไว้ก่อนที่ manual line จะอ้างอิงถึงทีละแถวได้) ไม่มีปุ่ม แต่ยัง
**กันที่ของปุ่มไว้เท่าเดิม** (`.manual-line-actions-empty`) เพื่อให้ตัวเลขของแถวรอบๆ ยังเรียงเป็นคอลัมน์เดียวกัน
พร้อม tooltip บนแถวบอกว่าทำไมถึงไม่มี

## ประเภท (เงินได้/หัก): แสดงแต่ล็อก ไม่ซ่อน

คอลัมน์ที่กด `+` ตอบคำถามนี้ไปแล้ว และแถวที่กดแก้ก็อยู่ในคอลัมน์ของมันอยู่แล้ว — ช่อง "ประเภท" จึงถูก
`disabled` ทั้งตอนเพิ่มและตอนแก้ แต่**ยังแสดง**อยู่ เพื่อให้ฟอร์มบอกได้ว่ากำลังทำรายการฝั่งไหน
(ปลดล็อกคืนตอน `hidden.bs.modal` เพราะ select2 ที่ถูก disable จะค้างอยู่อย่างนั้นจนกว่าจะสั่งกลับ)
