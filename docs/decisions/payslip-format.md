## Payslip Format (`Document & Approval` menu → "เทมเพลตสลิปเงินเดือน" tab, canvas designer since 2026-08-25)
- **2026-08-25, complete rebuild as a free-form canvas designer — explicit request: "ปรับให้การตั้งค่า Slip เงินเดือน Template เป็นเหมือนกับใบรับรอง" (make it like the Employment Certificate Template designer), confirmed via AskUserQuestion: a FULL canvas designer (drag/resize/ribbon/Layers/multi-page/Insert Table-Shape-Symbol/Image Library/presets/standalone editor page), not just matching page chrome.** The v1 ordered field-list architecture described below this bullet in earlier project history (`payslip_template_fields`, SortableJS drag-to-reorder, `custom_label_th/en` overrides, `buildTemplatedHtml()`) is **retired entirely** — `payslip_template_fields` was dropped outright (confirmed both it and `payslip_templates` were completely EMPTY in the real dev DB first, so this was a clean cutover with zero data-migration risk). Full detail — including 3 real bugs found and fixed while building this (a stale `name_th`/`name_en` INSERT left over from before those columns were dropped, the `Router::matchRoute()`-always-passes-strings gotcha on `editPage(int $id)`, and a leftover `.ect-preset-*` class-name copy/paste that would have coupled Payslip Template's visual styling to Employment Certificate Template's) — is not repeated here; see `PayslipTemplateModel`/`PayslipTemplateRenderer`'s own docblocks, which this section only summarizes.
- **Architecture mirrors Employment Certificate Template's own canvas designer almost exactly** (`PayslipTemplateModel`/`PayslipTemplateRenderer`/`PayslipTemplateController` are direct ports of `EmploymentCertificateTemplateModel`/`EmploymentCertificateRenderer`/`EmploymentCertificateTemplateController`, and `public/js/setup/payslip-template.js` is a direct port of `employment-certificate-template.js` — every generic canvas mechanism carries over unchanged: drag/resize, multi-select+Ctrl+Click+Group/Ungroup, Layers panel, Undo/Redo (`e.code` not `e.key`, same Thai-keyboard-layout fix), pan/zoom, grid overlay, page-margin guide (Word-style presets dropdown), Insert Table/Shape/Symbol, a reusable per-company Image Library (`payslip_images`, multi-select insert via the ribbon's Image dropdown), multi-page documents (`page_number`, one `.payslip-page` div per page + `page-break-after:always`), 3 starter presets (`classic`/`modern`/`minimal`) + blank in a Google-Docs-style gallery, and the standalone editor page opened in a new browser tab through the NORMAL `Controller::view()` layout (navbar/sidebar/breadcrumb — not bare) — see Employment Certificate Template's own v1-v12 history below for the full lineage/bug-fixes this inherits).
- **Two deliberate, real architectural differences from Employment Certificate Template, both because the two domains genuinely differ:**
  1. **NO pair_key/TH-EN-tabs at all.** Employment Certificate Template forks into two fully independent hand-authored layouts (one per language) because its content is mostly free text an admin writes themselves. Payslip Template stays **ONE shared canvas per template** — `language_mode` (`th`/`en`/`both`, unchanged from before this rebuild) governs which language bound DATA tokens resolve in at generate time (`PayslipTemplateRenderer::buildTokens()`'s own `pick()`), since payslip content is almost entirely data-driven tokens, not hand-authored prose needing two independent designs. The editor page is addressed by a plain `payslip_templates.id` (`payslip-template/edit/{id}`), not a pair key — state in the JS is a flat set of globals, no `pairState` swap mechanism.
  2. **`is_default`/`language_mode`/`header_text_*`/`footer_text_*`/`status` (active/inactive) are real, KEPT fields** — Employment Certificate Template has no equivalent of any of them (no company-wide "which one generates by default" concept, no header/footer text, no active/inactive toggle distinct from soft-delete). These live in a compact "Template Info" strip in the editor (`_editor_content.php`) between the top bar and the ribbon, and the list's Default-star toggle (removed from Employment Certificate Template's own list as redundant, see that module's v10) is **kept here** since `is_default` genuinely controls which template `PaySlipReport::generate()` picks.
- **`earning_lines_all`/`deduction_lines_all`/`statutory_lines_all` (the "block" fields) needed NO new element type or schema at all** — each is an ordinary `text` element whose content is exactly the single bound token (e.g. `{{earning_lines_all}}`), the SAME `{{field_key}}` convention every other bound field already uses (and the SAME content-pattern the JS's `isBoundFieldElement()` heuristic already locks against double-click editing, so the canvas needed zero special-casing). `PayslipTemplateRenderer::renderElementHtml()`'s text branch special-cases those 3 exact token strings to expand into a real itemized `<table>` (rows = the run's actual earning/deduction/statutory breakdown) instead of doing plain string substitution — this is the one piece of rendering logic with no equivalent anywhere in Employment Certificate Template.
- **Schema**: `master_payslip_field_types` gained `element_type` (`text`/`image` — only `company_logo` is `image`, mirrors Employment Certificate Template's own master table) and a new `static_text` field (free-form paragraph/label, same "Auto Replace" `{{field_key}}`-embedding mechanism), widening `field_group`'s enum with a 7th value `document` for it (the other 6 — `employee_info`/`company_info`/`earning`/`deduction`/`statutory`/`summary` — are unchanged from before). `payslip_templates` gained `page_size`/`orientation`/`margin_mm` (same enums/defaults as Employment Certificate Template's own) and had `name_th`/`name_en` **dropped** in favor of a single `template_name` (matching Employment Certificate Template's Word-doc-title-style naming — confirmed via grep that no other file in the app ever read those two columns before dropping them). New `payslip_template_elements` (template_id, element_type text/image/shape/table, field_key, image_asset_id → `payslip_images.id`, content, pos/width/height_pct, font_size/family/color, text_align/weight/style/decoration, sort_order, group_key, page_number) is the exact same shape as `employment_certificate_template_elements`. New `payslip_images` (company-wide reusable upload library) is the exact same shape as `employment_certificate_images`.
- **New permission `payslip_template.manage`** — the OLD `PayslipTemplateController` had NO permission gate at all; this brings it in line with Employment Certificate Template's own controller, which already gates every action this way. Seeded into `permissions`, shows up in the Permission Matrix automatically (dynamic query, no hardcoded list to update).
- **`PaySlipReport::generate()`** now delegates to `PayslipTemplateRenderer::renderForRun()` when the company has a default template with at least one element saved; if not (the common case for a company that hasn't set one up), falls back to the ORIGINAL fixed `buildHtml()` layout completely unchanged (same 100%-backward-compatible-until-opt-in behavior as before this rebuild) — `PaySlipReport` itself lost `buildTemplatedHtml()`/`generatePreview()`/`buildMockRunAndDetail()`/`pick()`/`statutoryLabelMap()`/`infoRow()`/`amountRow()`/`resolveTemplateOrCompanyLogo()` entirely (all superseded by their `PayslipTemplateRenderer` equivalents — the Preview endpoint now calls the renderer directly from `PayslipTemplateController::preview()`, no longer round-tripping through `PaySlipReport` at all).
- **Company Profile Logo fallback preserved unchanged** — `PayslipTemplateRenderer::resolveTemplateOrCompanyLogo()` (template's own `logo_path` first, `companies.logo_path` as fallback) replaces the old `PaySlipReport::resolveTemplateOrCompanyLogo()` 1:1, same priority as `EmploymentCertificateRenderer`'s own version.
- **Thai font bug fixed for Payslip Template's own canvas renderer, same as Employment Certificate Template's v2 fix** — `PayslipTemplateRenderer` has its own dompdf setup (TH Sarabun New registration + widened chroot), reusing the exact same bundled font files (`storage/fonts/thsarabun/`) — this is a genuine improvement over the OLD fallback path, which (like every other consumer of the shared `PdfRendererTrait`) very likely rendered blank Thai glyphs (DejaVu Sans has zero Thai glyph coverage, confirmed by parsing its cmap table during Employment Certificate Template's own v2 work). The OLD fixed-layout fallback (`PaySlipReport::buildHtml()`, still used when no canvas template exists) is **not** touched by this fix — same "known gap, deliberately out of scope" precedent Employment Certificate Template's own v2 already established for the shared trait.
- **2026-08-25, same-day follow-up bug + polish request** — reported as "Uncaught SyntaxError: Identifier 'currentTemplate' has already been declared" plus the editor page not visually matching Employment Certificate Template's: **real bug, not a guess** — `payslip-template.js` was ported from `employment-certificate-template.js` by copying its internal logic wholesale, renaming only DOM id/class prefixes (`ect`→`pst`), not the ~100 shared top-level JS variable/function names (`currentTemplate`, `elements`, `renderCanvas`, etc.). Since `payslip/settings.php` loads BOTH scripts on the same page, and both declared identical `let`/`const` names at the top level, the second script to parse threw a `SyntaxError` — which is a **parse-time** failure that kills the entire file, not just that line. That's why the editor didn't look right: `payslip-template.js` never ran at all, so nothing initialized (empty palette, unsized canvas, no ribbon wiring). Fixed by wrapping BOTH files' entire contents in their own IIFE (`(function () { ... })();`), scoping every top-level declaration to that closure — verified via a Node `vm` sandbox that both scripts now load and execute together with zero errors. Also surfaced (and fixed) a real test-isolation bug in the process: `tests/payslip_template_test.php`'s cleanup step set `status='deleted'` but not `deleted_at`, and `PayslipTemplateModel::list()`/`get()` filter on `deleted_at IS NULL` (not `status` — unlike Employment Certificate Template, which filters on `status` only) — so a real template the user had created while testing live ("Slip เงินเดือน") was leaking into the test run. Fixed the isolation query in both `payslip_template_test.php` and `reports_test.php`.
