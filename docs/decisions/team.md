## Team (Organizational Structure → 7th sub-tab "Team", `structure_teams`; also on Employee list/detail)
- **2026-08-24, explicit request: "ในหน้าตั้งค่าพนักงาน ให้เพิ่ม Team เข้าไปได้ด้วย (ในความหมายคือ เป็นบริษัทที่จ้าง outsource เพื่อไปอยู่กับหลาย Project...) ...ทีมให้เป็นการเพิ่มการตั้งค่าเช่นเดียวกับ Department แล้วดึงมาใช้ และเพิ่ม Filter ทีมในหน้า list พนักงานด้วย"** — the company running this app is itself an outsourcing/staffing firm; "Team" is the grouping of its own employees deployed together to one client/project, independent of their formal Department/Position in the firm's own org chart. Naming ("ทีม"/"Team", not "Project Team"/"Client Site") and whether it needs a client/scope field beyond code+name (yes) both confirmed via AskUserQuestion before building.
- **Schema**: `structure_teams` — same shape as `structure_departments` (`team_code`, `team_name_th`, `team_name_en`, per-company, soft-deletable, `uq_comp_team_code` unique on (comp_id, team_code, deleted_at) with the usual app-layer re-check per this project's own deleted_at+unique convention) plus one extra column `client_name` (free text, nullable, NOT split into _th/_en — a client's name isn't something that gets translated, same precedent as `structure_departments.cost_center` being a single free-text field). `employees.team_id` — nullable FK (`ON DELETE SET NULL ON UPDATE CASCADE`), placed right after `department_id`.
- **Backend is 100% additive to already-generic dispatchers, no new CRUD engine written**:
  - `CompanyProfileModel::structureConfig()` gained a `'team'` entry — the exact same generic `saveStructure()`/`deleteStructure()`/`isStructureValueDuplicate()` methods that already serve branch/role/department/position/rank handle Team with zero new code.
  - `CompanyProfileController::team()` (list, mirrors `department()`'s own `paginateData()` call verbatim) + `teamSave()`/`teamDelete()` (one-line dispatchers to `handleStructureSave('team')`/`handleStructureDelete('team')`, same as every other entity). Permission: reuses `company_structure.view`/`company_structure.manage` — no new permission key.
  - `MasterModel::master()` gained a `'team'` case in its existing generic table-driven select2-ajax resolver (just one row in `$tableMap`) — this is what `data-api="/api/team.get" data-type="team"` (Employee Detail's dropdown, Employee List's filter) actually calls.
  - Routes: `api/structure.team` (list), `api/structure.team.save`/`.delete`, `api/team.get` (dropdown options) — same naming pattern as department's equivalents.
- **Frontend (Organizational Structure tab)**: pill (`structure-tab-p7`/`data-page="p7"` — **appears BEFORE Permissions visually since the 2026-08-24 follow-up below, `data-page`/id left as "p7" on purpose, only the `<li>`'s DOM position moved, so `company-profile.js`'s `initStructure()` switch needed zero changes**) — `initStructure()`'s switch, `getStructureColumns('team')`, `formSchemas.team`, and `apiEndpointPrefix.team` in `company-profile.js` all follow the exact same schema-driven pattern department/position/rank already use (the Add/Edit modal's fields, validation, and payload are entirely driven by `formSchemas.team.fields` — no bespoke modal markup was written). `#tmpl-team-pane` mirrors `#tmpl-department-pane`'s table markup.
- **Employee Detail**: optional dropdown (`select2-remote`, `data-api="/api/team.get"`) in the Employment tab's "Corporate Information" section — deliberately **NOT** `.required` unlike Department/Role/Position/Branch, since not every company using this app is a staffing firm; not added to `requiredColumns()`/`completenessColumns()`/`requiredFieldTabs()` either, so an empty Team never blocks save or dents profile completeness %. **`team_id` had to be added to BOTH `detail.js`'s `remoteFields` array AND get an explicit `populateSelect2Field('team_id', ...)` call** — skipping either one reproduces the exact silent-data-loss bug already documented on this same page for `work_location_id`/`shift_id` (a `select2-remote` with no `<option>` preloaded yet silently ignores a plain `.val(id)`, so the field reads empty and overwrites the real saved value on the next save). **Paired with Position** (2026-08-24 same-day follow-up, "team อยู่รายการเดียวโดด...ย้าย select ตัวต่อไปมาไว้ให้เป็นคู่") — every field from Position onward shifted up one row-slot to close the gap (Employee No.+Branch, Work Location+Shift), leaving Employment Date alone at the very END of the section instead of Team alone in the MIDDLE.
- **Employee List**: filter dropdown (`#employee_filter_team`, same `select2-remote ajax` pattern as the Department/Role/Shift/Branch filters beside it) plus a **Team column** inserted right after Department in both the table markup and `EmployeeModel::list()`'s SELECT/JOIN/`sortColumns` index map — inserting a column mid-list means every column index in `sortColumns` from that point on shifts by one (verified end-to-end via direct `EmployeeModel::list()`/`get()`/`save()` calls through PHP CLI, not just code review, including that an invalid/cross-company `team_id` is correctly rejected the same way `department_id` already is).
- **2026-08-26, explicit request: "เพิ่ม position กับเบอร์โทรเข้าตาราง"** — two more columns added the same way, both LEFT JOINs (`structure_positions p ON e.position_id = p.id`; `mobile_no` was already selected as `phone` in the SELECT list from before this, just never rendered as a column) — **Mobile No. inserted right after Name, Position inserted right after Role** (contact info clustered with identity, org placement clustered together), shifting every later `sortColumns` index by 2 total (department/team/shift/branch/start_work_date/status all moved). Verified via direct `EmployeeModel::list()` calls through PHP CLI that every remaining sort index (department through status) still resolves to the correct column after the shift, not just that the new two do.
- **Organizational Structure tab order (2026-08-24 same-day follow-up, "ในหน้าตั้งค่าย้ายทีมมาไว้ก่อน permission")** — Team's pill moved to appear before Permissions. Pure DOM reorder of the two `<li>` blocks in `company-profile.php`; `data-page`/`id` values on both buttons are untouched, so `initStructure()`'s `switch(page)` dispatch needed no code change at all -- only visual tab order moved.
- **Join Employees picker (Payroll Process → off-cycle run → "Join Employees" modal) also got the Team filter** (2026-08-24 same-day follow-up, "ในการดึงพนักงานเข้ามาเพื่อคำนวณเงินเดือน ให้มี Filter ส่วนที่เพิ่มเมื่อสักครู่ด้วยครับ และจัดรูปแบบให้การดึงพนักงานเข้ามาในการคำนวณดำเนินการได้ง่ายที่สุด") — `PayrollRunModel::manualEmployeeOptions()`'s WHERE-building (pure-cycle-run re-include-only branch + sync-run already-mapped exclusion + every filter) was extracted into a new shared private `buildManualEmployeeWhere()` so a new `team_id` filter didn't have to be duplicated, and so a brand-new **`manualEmployeeAllIds()`** method (id-only, NOT paginated) could reuse the exact same WHERE. That new method backs a new **"Select All Matching (N)"** button in the picker (`api/payroll-run.manual-employee-all-ids`) — the existing header checkbox only ever selects the CURRENT DataTable page (`serverSide:true`), which made bulk-pulling a large filtered set (e.g. "everyone on Team X") tedious across many pages; this is the "ดำเนินการได้ง่ายที่สุด" (make it as easy as possible) part of the request, not just the filter itself. The picker's own `team_id`/other filters double as the payload for this new endpoint too (same filter state, two different queries: paginated table vs. unpaginated id list).
- ยังไม่มี dedicated test file สำหรับ `CompanyProfileModel`'s structure CRUD (branch/role/department/position/rank ไม่เคยมี test แยกมาก่อนเช่นกัน — pattern นี้ proven ผ่านการใช้งานจริงมาแล้ว 5 entity types) ยืนยันด้วย PHP CLI smoke test แทน (create/duplicate-reject/delete ผ่าน `CompanyProfileModel`, save/get/list-filter/invalid-FK-reject ผ่าน `EmployeeModel`, และ `manualEmployeeOptions()`/`manualEmployeeAllIds()` ผ่าน `PayrollRunModel`) — ถ้าจะเพิ่ม dedicated test ทีหลังสำหรับ Organizational Structure CRUD ทั้งชุด ควรทำเป็นไฟล์เดียวครอบคลุมทุก entity type ไม่ใช่แค่ team
