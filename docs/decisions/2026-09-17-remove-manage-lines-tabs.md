# สลิปที่แก้ได้ — D3: ลบ tab ที่ย้ายไปสลิปแล้ว (2026-09-17)

D1/D2 ย้ายตาราง line-override + block "รายการที่เพิ่มเอง" เข้า `#runDetailBreakdownModal` แล้ว tab "รายการจ่าย"/"ปรับตัวเลข" จึงเป็น
ทางเข้าที่สองของสิ่งเดียวกัน ลบทิ้งทั้งคู่ · 3 tab ที่เหลือเป็น**ค่าตั้งของพนักงานคนนั้นในรอบนั้น** ไม่ใช่ตัวเลขของเขา จึงเปลี่ยนชื่อเป็น "ตั้งค่ารายบุคคล" ·
badge `adjustment_count` ย้ายไปปุ่มแว่น = ปุ่มที่เปิดที่ที่รายการพวกนั้นถูกแก้จริงแล้ว (ตัวเลขเท่าเดิม)

**"คืนค่าระบบทั้งหมด" ย้ายตามตาราง ไม่ใช่ตามเจ้าของเดิม** — สิ่งเดียวของ tab "ปรับตัวเลข" ที่ยังไม่เคยย้าย ผู้ใช้เลือกให้ไปอยู่ footer ช่องซ้าย (§9) ของ
`#runDetailBreakdownModal` พร้อมบรรทัดความคืบหน้า · modal นั้นเคยไม่มี `.modal-footer` ใน markup เลย (`data-footer="view"` ของ app.js ฉีด
`[ปิด]` ให้) ตอนนี้สร้างเองด้วย `modalFooterButtonsHtml()` ต่อการเปิด 1 ครั้ง — แถวที่แก้ไม่ได้ได้ `[ปิด]` เดี่ยว ๆ เท่าเดิมเป๊ะ

**`.modal-tabbed` ถอดออก** — วัดจริง (viewport 950, light, run ทดสอบที่สร้าง/ลบทิ้งแล้ว ไม่ใช่ 752), `.modal-content`:

| tab | เนื้อในจริง | คงไว้ | ถอด @1400 | ถอด @430 |
|---|---|---|---|---|
| ข้อมูลเข้างาน | 321.5 | 853 | **587** | **587** |
| ปลายทางรายการหักประจำ | 81.5 | 853 | **347** | **362.75** |
| ภาษี & ประกันสังคม | 161.25 | 853 | **426.75** | **442.5** |

ตอนรับมาใช้ (2026-09-15) tab สูงสุดสูง 826–851 อยู่แล้ว ตรึงที่ 750 จึงไม่เสียอะไร · เหลือ 3 tab สั้น tab สูงสุดกิน body ที่ตรึงแค่ 43% (ว่าง 428.5px)
เตี้ยสุด 11% (ว่าง 668.5px) = เข้าข้อยกเว้นของ §9 เอง แลกกับกระโดด 240px (@430 = 224.25) ที่ผู้ใช้ตัดสินใจรับ · ถอด `modal-fullscreen-sm-down`
พร้อมกันตามกฎ (เหลือไว้ลำพัง = ช่องว่างตาย 97px ท้าย modal เต็มจอ, วัดได้) · พอไม่เหลือใครใช้ **ลบ CSS `.modal-tabbed` ทิ้งทั้งก้อน** และแทนกฎใน §9 ด้วยบรรทัดยกเลิก
