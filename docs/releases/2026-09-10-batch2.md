## What changed, by item

**Item 1 — Approval Timeline modal: History section removed** (List page + Approval Queue page
only; Detail page's own timeline modal untouched, it has a separate full tab elsewhere)
- `PayrollController::approvalTimeline()` no longer fetches `audit_log`
- `renderAuditTimelinePr()`/`renderAuditTimelineAp()` and their History section markup removed from
  `public/js/payroll/index.js` / `approval.js`

**Item 2 — Real employee photos in the Timeline modal** (List, Approval Queue, and Detail pages)
- `apvAvatarHtml{Rd,Pr,Ap}()` now render `<img>` from `profile_photo_path` (same field/URL
  convention as Employee List's own avatar column), `escapeAttr()`-escaped, with an `onerror`
  fallback to the initial-letter circle (`apvAvatarImgError{Rd,Pr,Ap}()`, reads size/initial back
  off `data-*` attributes rather than embedding raw strings inside the `onerror` attribute)
- `PayrollRunModel::approvalFlow()` (both branches) and `ApprovalRequestModel::currentStepApprovers()`/
  `stepBreakdown()` SELECTs gained `profile_photo_path`

**Item 3 — Detail page row-level Verify button: distinct before/after states**
- `verifyLockButtonsRd()`'s draft-branch button: outline + "ตรวจสอบ" (not yet verified) vs.
  filled-success + "ตรวจสอบแล้ว" (verified) — readable in grayscale, not just icon color. Existing
  i18n keys reused (`action_verify`/`verify_status_verified`), no new ones.

**Item 4 — Process List: origin/type badges + employee-count column**
- Icon-only, hover-tooltip-only `runOriginBadgePr()`/`runTypeIconPr()` (cloud / gift) replaced with
  short visible TEXT badges, shown ONLY for the exception case (Origami-synced run / incentive run —
  a normal cycle-based `payroll` run gets no badge at all), positioned after the run name
- Employee-count column consolidated to one line, right-aligned, no icon. Format keyed on the RUN's
  `state`: draft/pending_approval/need_info/rejected always show
  `{verify_status_verified} {verified}/{total}` (even when verified=0); approved/paid/locked/cancelled
  show just `{total}`
- New i18n keys: `run_origin_origami`, `run_type_special`

**Item 5 — Process List sync-detail modal, section 1: cards → DataTable + child rows**
- Part A: `.sync-emp-card-list` replaced with `#tb_sync_items` (client-side DataTable, 10 columns:
  code/name/dept-position/working days/absent days/late mins/OT hrs/trip allowance/mapping
  status/SSO status), numeric columns right-aligned tabular via object-form `render:{display,sort,filter}`,
  3 filter pills (all/unmapped/SSO-not-set, counts in parentheses), unmapped rows highlighted
  (`.table-danger`) and sorted first by default
- Part B: expand/collapse control column (leftmost), child row groups `item_values` by `item_code`
  onto one line each (e.g. `Absent: 24.00 time(s) · 24.00 day(s) · 164.00 hour(s)` instead of 3
  separate badges), plus detailed OT-by-scope breakdown, payment method/SSO, masked ID card,
  probation status. `preDraw.dt` closes any open child row before every redraw (search box, filter
  pills, sort, paging) so nothing goes stale.
- Cleanup: `renderSyncItemCardPr()`/`syncEmpExtraStatsPr()` and all `.sync-emp-card-*`/`.sync-emp-stat-*`
  CSS deleted (confirmed zero remaining references app-wide before deletion) — the structured
  `early_mins`/`leave_approve_days`/`leave_wait_days`/`leave_without_pay_days` fields the old card
  showed are now displayed in the child row as a fallback (same i18n keys), shown ONLY when the
  matching `item_values` group (EARLY_LEAVE/LEAVE_APPROVED/LEAVE_PENDING/UNPAID_LEAVE) is absent, to
  avoid showing the same number twice under two labels
- Bug fix caught mid-batch: OT-hours unit in the child row/card was a hardcoded `h` suffix
  regardless of language — now uses `langData['sync_unit_hours']` like every other unit label

**Item 6 — Reports > Annual Income & Tax Summary: new SSO tab**
- New tab "สรุปเงินสมทบประกันสังคมประจำปี" inserted directly after the tax (PIT) tab — same fiscal-year
  filter set, same 2-stat-card row, same plain table (sticky columns, drag-scroll), same cell
  click-to-drill-down modal. **No export** — confirmed the tax tab it mirrors has no export capability
  on this page either (page is deliberately interactive-only, not a generate-and-download report)
- Tracks employee-side SSO only (`statutory_breakdown`'s `TH_SSO` line, `employee_amount` — confirmed
  via AskUserQuestion, not employee+employer combined)
- New route `api/annual-income-summary.sso-summary`, new i18n keys `ais_tab_sso_annual`/`ais_total_sso_withheld`
- Internal refactor (explicit follow-up, before committing): `annualPitSummary()`/`rawPitRows()` and
  `annualSsoSummary()`/`rawSsoRows()` consolidated into one generic
  `annualDeductionSummary(string $statutoryCode, string $amountField, ...)` /
  `rawDeductionRows(string $statutoryCode, ...)`, with the 2 original methods kept as thin wrappers
  so no caller's return shape changed. `rawPitRows()` itself also kept as a thin wrapper (not deleted)
  because `monthlyPitDetail()` calls it directly and reads its `tax_withheld` key. Verified
  byte-identical output via PHP CLI against real comp_id=1 data (PIT 341.66 / SSO 3,000, both 27
  employees) before and after.

**Item 7 — Detail page employee table: reduced density**
- Excel-filter icon restricted to columns with real discrete values (data source, payment method,
  calc status, verify status) — removed from the 4 numeric amount columns and the name column
- Row actions: `btn-view-breakdown` stays the one visible button; Raw Sync Data/Manage Items/
  Comment/Remove collapsed into one "More" (⋮) dropdown, same classes so click handlers needed zero
  changes. Fixed mid-item: the dropdown was clipped by `.table-responsive`'s own `overflow-x:auto`
  (same root-cause class already documented for `tb_cycle_matrix` in `reports/index.js`) — fixed via
  `strategy:'fixed'` Popper config; Remove now sits below a divider, only shown when there's
  something above it to divide from
- Column headers: `text-nowrap` added to every header with real text (Bootstrap utility, no new CSS)
