**Deploy step, added retroactively (Batch 3B item 0 introduced `scripts/migrate.php` the same
day this note was first written — this replaces any earlier "run these 2 files with mysql"
instruction, which is exactly the practice that broke production once, see that batch's own
release note):**

- If the target database has run `scripts/migrate.php` before:
  `php scripts/migrate.php status && php scripts/migrate.php up`
- **First deploy to a NEW environment** (this batch is likely the first time this happens, since
  the tool didn't exist until today) is 4 steps, not 2:
  1. `php scripts/migrate.php status`
  2. Manually check every file `status` lists under "Unknown" against that environment's real schema
  3. `php scripts/migrate.php mark <file>` each one confirmed already applied (or apply it
     deliberately some other way, then `mark` it)
  4. `php scripts/migrate.php up` — only now; it refuses to run anything while any file remains
     unresolved in "Unknown"

Rollback, if ever needed, in reverse of apply order: `php scripts/migrate.php down
2026-09-10_2_add_sso_pvd_lookup_lists_and_fields.sql` then `php scripts/migrate.php down
2026-09-10_add_pvd_employer_rate_ladder.sql`.

## What changed, by item

**Item 1 — Dropdown clipping inside DataTables, fixed globally (not per-table)**
- New `applyFixedStrategyToTableDropdowns()` in `app/js/app.js`, triggered on every `draw.dt` +
  document ready: reconfigures any `.dropdown-toggle` inside a `.dataTables_wrapper`/
  `.table-responsive` to Popper `strategy:'fixed'`, escaping the wrapper's own `overflow` clipping.
  Uses `bootstrap.Dropdown.getOrCreateInstance()` (verified idempotent from Bootstrap's own source)
  so re-running on every redraw never double-inits.
- Removed 2 now-redundant per-table fixes: `tb_cycle_matrix`'s own drawCallback fix
  (`public/js/reports/index.js`) and `tb_run_detail`'s own (`public/js/payroll/detail.js`).
- Covers all 5 tables app-wide known to have in-cell dropdowns: `tb_payroll_run`, `tb_run_detail`,
  `tb_cycle_matrix`, `tb_ect_template`, `tb_pst_template`.

**Item 6 — Payroll Configuration: dropdowns with ≤3 options → segmented buttons**
- `#itemModal` (Earning/Deduction Types Add/Edit): 4 fields converted from `<select>` to
  `.btn-group` segmented toggles — `tax_treatment`, `tax_deduction_impact`,
  `statutory_report_code`, `default_fee_base`. Short button labels + full original text as a
  tooltip (new i18n keys, existing keys left untouched).
- One shared `setPedSegmentedValue()` setter (not 4 copies) in
  `public/js/setup/payroll-configuration.js`; validation now adds a visible border on the toggle
  container (a hidden `<input>` alone has no `.is-invalid` visual).
- `amount_source`/`default_interest_type` (4 options each) deliberately left as `<select>` — over
  the 3-option threshold.

**Item 2 — Payroll Timeline (List + Detail): one shared 5-step lifecycle mapping**
- New `RUN_LIFECYCLE_STEPS`/`RUN_LIFECYCLE_BRANCH_INFO`/`runLifecycleSteps(run, {showDates})` in
  `app.js`, replacing 3 drifted per-page copies in `detail.js`/`index.js`/`approval.js`. Steps:
  draft → pending_approval → approved → paid → locked, with 3 branch types (rejected/need_info/
  cancelled) overlaid at whichever step they actually happened from.
- List's mini-timeline shows no dates (has its own "Last Updated" column); Detail's full spine
  shows dates, sourced from `run.audit_log` when present, falling back to the run row's own
  `*_at` columns when it's absent (fixes a real regression risk found before shipping — the List/
  Approval Queue's own `approvalTimeline()` endpoint doesn't carry `audit_log` at all).

**Item 3 — Approval Timeline modal: Paid/Locked split into 2 stations + real creator photo**
- `PayrollRunModel::get()` gained JOINs for `paid_by`/`locked_by`/`created_by`'s own
  name/photo — the old single merged "Paid & Locked" box is now 2 real stations
  (`apvPaidStageHtml()`/`apvLockedStageHtml()`), each with its own who/when.
- Consolidated `APV_COLORS`/`apvBadgeHtml`/`apvIconHtml`/`apvAvatarHtml`/`apvPersonLineHtml`/
  `apvCreatedStageHtml` into `app.js` (were 3 duplicated copies across detail/index/approval.js).
- Fixed a PHP parse error (literal Thai quote marks inside a PHP double-quoted SQL comment) caught
  by `php -l` before shipping.

**Item 4 — Employee avatar (extended, not duplicated) + quick-view modal**
- `apvAvatarHtml()`/`apvPersonLineHtml()` extended with an optional 4th `options.employeeId` param
  (click-to-view) instead of creating a second avatar function, per explicit instruction.
- New `EmployeeModel::quickView()` / `EmployeeController::quickView()` /
  `api/employee.quick-view`, new `#employeeQuickViewModal` (photo, name, dept/position/branch,
  status, link to full profile).
- Wired into List's "Updated By" column and Detail's employee-table name column; the timeline
  modal's Created/Paid/Locked stages (item 3) also became clickable this way.

**Item 5 — Detail employee table: "Adjusted N" badge replacing the fa-sliders icon**
- New `PayrollRunModel::employeeAdjustments()` combines current line overrides (enriched with real

- Badge count (`line_override_count + manual_line_count`) replaces the old bare icon; clicking it

  `payroll_run_line_overrides`/`payroll_run_line_override_history`/`payroll_run_manual_lines`.

**Stacked-modal fix (bundled into the item-5 commit, pre-check before item 5)**
- Bootstrap 5's own `Modal._hideModal()` unconditionally strips `modal-open`/scroll-lock/scrollbar
  padding from `<body>` on every close, with no awareness of another modal still open underneath
  (verified from Bootstrap's own bundled source, not guessed) — broke the Approval Timeline modal's
  scroll/backdrop when the new Employee Quick-View modal (item 4) was opened on top of it and closed.
- New global `hidden.bs.modal` handler in `app.js`: re-applies `modal-open` + `overflow:hidden` +
  the correct scrollbar-width padding whenever another `.modal.show` is still present after a close.

**Item 7a — PVD employer contribution ladder by tenure + wiring dead rate-override columns**
- New `company_pvd_employer_rate_ladders` (Setup > Tax & Statutory, opt-in tier list: years-of-
  service → employer %, 0 rows = unchanged flat rate) via new `PvdEmployerRateLadderModel`.
- **Real gap found and fixed**: `employees.pvd_employee_rate`/`pvd_employer_rate` existed on the
  Employee Detail form but were never read by `StatutoryCalculationEngine`/
  `PayrollRunModel::recalculate()` at all — now wired into the same `$employeeRateOverrides`
  channel TH_SSO's own per-employee rate override already used. Priority: employee override >
  ladder tier (tenure counted **as of the run's own `period_end_date`**, not "today") > company/
  master default. Resolved source/tier stamped onto the TH_PVD breakdown item for audit.
- CLAUDE.md's Database section rewritten per explicit instruction: migrations may only be applied
  to the local dev DB, never ad-hoc DDL without a file first, every task summary must report a
  migration was applied and how to roll it back.
- **Impact on existing employee data** (see dedicated section below) — zero employees affected.

**Item 7b — SSO Hospital/Leaving-Reason + PVD Investment Plan/Fund fields**
- New generic `CompanyLookupListModel` (one model, not two) backs both SSO Hospital and PVD
  Investment Plan as per-company Select2 "tags" lists (pick existing or type new, case-insensitive/
  trimmed dedup, auto-created on employee save) — no real government hospital master list exists to
  seed in this environment (confirmed with the user).
- `MasterModel::master()`'s existing generic comp-scoped select2-ajax resolver reused (`'hospital'`/
  `'pvd_plan'` added to its table map) — no new list-endpoint code.
- SSO Leaving Reason is a **fixed 7-option dropdown**, not free text or a lookup list — text
  extracted directly from the real official สปส.6-09 PDF (sso.go.th), not guessed or translated
  loosely; shown to the user for comparison against the real form before shipping.
- New PVD fields: fund manager (AMC), member no., membership end date + reason (free text, same
  convention as the existing general `employment_end_reason`).
- Live "company default rate" helper text added for SSO's employee/employer rate overrides and
  PVD's employee-rate override (PVD's employer-rate helper already shipped in item 7a).

## Impact on existing employee data (PVD rate wiring, item 7a)

Investigated and reported before shipping, not assumed:
- **Zero employees, in any company in this dev DB, have `pvd_employee_rate` or
  `pvd_employer_rate` set** (`SELECT COUNT(*) FROM employees WHERE pvd_employee_rate IS NOT NULL
  OR pvd_employer_rate IS NOT NULL` → 0 rows) — these fields were `d-none`-hidden in the UI from
  2026-08-19 until this batch, and no sync/import path ever wrote to them either (confirmed via
  grep). **No real employee's payroll is retroactively affected by this wiring.**
- **Approved/paid/locked runs cannot be recalculated by this change under any circumstance** —
  `PayrollRunModel::recalculate()` refuses outright (`"Only a draft payroll run can be
  recalculated."`) unless `run.state === 'draft'`; every one of the 17 call sites in the codebase
  goes through this same guard. A run that has already left draft state keeps its original stored
  TH_PVD amounts forever, regardless of this change.
- Because no employee currently has either override set, there is no draft/pending run today whose
  TH_PVD figure would change once this ships — no before/after comparison table was produced
  because there is nothing to compare. **This only takes effect the next time someone (a) sets one
  of these 2 fields on an employee, or (b) configures a PVD employer-rate ladder for a company, and
  then recalculates a draft run for an employee in scope.**
